# Messages 1.6.0 product audit and improvement plan

**Date:** 2026-10-06  
**Scope:** current Android source, current in-progress working tree, project documentation, installed package metadata, and public product documentation for Google Messages, WhatsApp, and Telegram.

## Inspection boundary

The on-device package inventory showed `com.messages.app` as the installed default SMS app and `com.messages.app.debug` as the separate modified build. The debug package was uninstalled as requested; the default package remains installed and retains the SMS role. No SMS/MMS bodies, conversation screenshots, or accessibility dumps were collected for this audit. The device UI could not be visually reviewed in this session, so screen-specific judgments below are grounded in source and the existing 2026-10-06 product review rather than a fresh visual inspection.

The active Git tree already contained user changes in UI, motion, message processing, model data/training, update handling, and privacy copy. These changes were preserved and are part of the versioned build. The model scorer remains optional; its evaluation gate is still open.

## Current product assessment

Messages is an Android default SMS/MMS client with a differentiated local-first protection model. It treats message classification as reversible organization: Spam, Promotions, Blocked, and Review remain browsable, searchable, and restorable. It also provides dual-SIM handling, drafts, scheduling/outbox, contacts, archive/trash, search, notifications, widgets, backup, and a secret locked space.

The current source has a coherent violet/Material 3 visual system and shared animation primitives. Home rows combine sender, preview, time, mute/unread, and pin state; the home surface includes category navigation, search filters, selection actions, swipe actions, and a compose FAB. Chat includes grouped bubbles, inline timestamps/delivery status, attachments, SIM selection, scheduling, quick replies, search, starred messages, link previews, fraud warnings, and contact details. Contact details now surface starred messages/search and notification controls. Settings are divided into reusable sections and rows. Motion honors the system animation preference, and selected progress/control semantics have accessibility descriptions.

## Comparison and product implications

| Product | Strong patterns worth learning from | Relevance to Messages |
|---|---|---|
| Google Messages | Search filters include unread, known/unknown senders, starred, SIM, and media types; RCS adds high-resolution media, typing/read status, group management, and optional end-to-end encryption for eligible Google Messages chats. | Keep Messages’ folder organization, and consider adding sender/SIM/media facets to search. RCS is a platform limitation for third-party default-SMS apps, not a UI feature this project can implement alone. Google’s spam documentation also makes clear that its protection can include URL checks sent to Google; Messages’ local-only classification remains a meaningful privacy distinction. |
| WhatsApp | Chat Lock hides locked chats behind authentication and suppresses contact/message details in notifications; communities and richer internet messaging support group and business workflows. | Messages already has a secret locked space and local encryption. Continue making notification privacy and the shared-SMS-provider limitation explicit. Avoid implying that app-local locking removes messages from Android’s shared telephony database. |
| Telegram | Chat folders, archive behavior, per-chat themes, and cross-device synchronization support users with many conversations and customization needs. | Messages already has folders, archive, per-chat styling, and backup. Its SMS-provider data model cannot provide Telegram-style cloud synchronization without introducing a separate messaging service and its trust/security obligations. |

## Improvement priorities

**Implemented in 1.6.1:** Conversation rows now expose the configured swipe action through TalkBack custom actions with state-sensitive labels, and swipe feedback uses the shared reduced-motion-aware motion system.

### P0 — release confidence

1. Finish a message-free device visual pass for Home, Chat, Contact Details, Settings, onboarding, empty/error/loading states, large font sizes, TalkBack, and reduced motion. Use synthetic content or a clean test profile; do not capture real conversations.
2. Complete the held-out false-positive evaluation for the optional local scorer before recommending that users enable it or making efficacy claims.
3. Resolve the documented Android Gradle Plugin / compile SDK compatibility warning, then run the project’s established test suite and release checks before public distribution.
4. Replace privacy-policy publisher/contact/effective-date placeholders before public distribution.

### P1 — usability polish

1. Verify category navigation and unread badges at narrow widths, large text scales, and with all folders active; ensure the less-frequent Blocked/Archived/Outbox surfaces remain discoverable.
2. Extend search with known/unknown sender, SIM, and media facets if they can be added without crowding the current filter controls.
3. Complete localization beyond resource extraction: provide translated resource sets and verify date, plural, and 12/24-hour formatting end-to-end.
4. Finish branded monochrome notification glyph and app-icon review at actual launcher/notification sizes.

### P2 — future product scope

1. Consider a personal highlights view only after validating whether users need a separate summary surface; keep it evidence-based and avoid inferring mastery or message importance from incomplete signals.
2. Keep RCS on the platform roadmap only if Android exposes a supported third-party path. Do not emulate delivery/read states over SMS.
3. Add exportable, synthetic demo data and a privacy-safe visual QA harness so future reviews do not depend on personal inbox contents.

## Tool and resource check

- **Figma:** no Figma connector is available in this session. It is not required for this release: the app’s Compose design system and existing UI source are editable here. Connect Figma only if you want externally maintained design files or collaborative prototype review.

- **Public release:** GitHub/Play publishing is a separate distribution step. This session has not published the APK or changed any repository history.
